# 照片查看器导航面板与高分辨率缩放设计

- 决策日期：2026-10-20
- 状态：提案，待讨论；本文不代表已实现或已验证上线
- 范围：PC 与移动 Web 普通照片查看器（PhotoViewer）；不包含原生 Flutter 应用
- 代码核查基线：`0xca71/gallery main c90a67529c5294b2a9e6dddf1dabf6a6e4e6586e`

## 目的与术语

放大查看照片时，用户需要知道自己正看整张照片的哪一部分，并能直观地调整倍率、移动到另一处。新增右上角的导航面板（Navigator），PC 版由全图导航缩略图、可视区域框（viewport rectangle）和缩放滑块（zoom slider）组成；移动 Web 版保留导航缩略图与可视区域框，通过手势调整倍率，不显示缩放滑块。

这是照片查看器内的导航，与时间线的缩放导航不同。导航缩略图本身可以使用小图；主图立即使用当前完整预览图响应缩放与移动，同时后台尝试加载原图或可解码的高分辨率来源，成功后保持当前视角替换。加载速度或失败不阻塞交互，也不重置倍率和位置。

术语参考：[GIMP Navigation Dialog](https://docs.gimp.org/2.10/en/gimp-navigation-dialog.html)，其全图预览、可视范围与倍率滑块对应同类交互。

## 当前行为与问题

核查的是源码和已安装依赖，未连接线上实例抓取实际照片请求，也未进行浏览器回归。

| 环节 | 当前代码行为 | 对设计的影响 |
| --- | --- | --- |
| 缩放输入 | `AssetViewer.svelte` 保留 Alt＋滚轮缩放、普通滚轮切图；`PhotoViewer.svelte` 支持双击、Z 和工具栏缩放；`zoom-image.ts` 使用 `@zoom-image/core` | 保留现有输入习惯，新增面板共享同一缩放状态 |
| 清晰度加载 | `AdaptiveImage.svelte` 在实际 `zoom > 1` 后触发名为 `original` 的质量层 | 保留缩放立即响应与异步加载，补齐无跳动替换、独立加载状态和失败提示 |
| 浏览器可解码图片 | `web/src/lib/utils.ts` 的 `targetImageSize` 在强制原图时选择 original endpoint | 普通兼容图片已有原图请求路径，不能笼统认定一直在放大小缩略图 |
| 浏览器不兼容格式 | 同一方法选择 fullsize endpoint | RAW 等需要转换或提取后的可显示图，不能直接把不可解码原文件塞入 img |
| fullsize 缺失 | `AssetMediaService.viewThumbnail` 会重定向回 preview | “original 层加载成功”不等于原图或全尺寸图真实可用 |
| RAW 内嵌图 | `MediaService.extractOriginalImage` 可使用内嵌 JPEG 生成或保存 fullsize | fullsize 是来源类别，不应无条件宣称等于传感器原始分辨率 |
| 已编辑图片 | 媒体 URL 默认携带 `edited=true`，原图服务可返回 editedPath | 放大后应继续显示用户看到的编辑结果，不能突然显示未编辑版本 |
| 分享限制 | `getAssetUrl` 对不允许下载或不显示元数据的分享返回 preview；原图接口检查 AssetDownload 权限 | 不可用直接原图请求绕过权限；受限情况下需明确画质状态 |
| Chromium 渲染 | `AdaptiveImage.svelte` 有 HDR 接缝和 GPU 栅格预算处理 | 已加载原图仍可能受渲染分辨率限制，不能以移除保护换取潜在缺块 |

## 建议的交互

### 显示与布局

感知到放大手势或操作开始时，右上角导航面板渐显（从透明到可见）；回到适应窗口时渐隐。此处将需求中的“淡出显示”理解为淡入出现。渐显不等待原图加载，也不延迟主图缩放；支持减少动态效果的系统设置，出现/消失动画不阻塞操作。面板位于顶部工具栏下面，默认宽约 180–220 CSS 像素，使用现有主题的深色半透明背景、细边框与适量圆角。

面板相对实际照片可视区域定位。打开详情或活动侧栏时，避开侧栏；工具栏显隐不应使面板跳动。高度受可视区域限制，竖图不能占满屏幕。移动 Web 收窄面板，只保留导航图、可视区域框和必要状态提示，不显示滑块或加减缩放按钮。横竖屏切换、浏览器可视高度变化后仍需避开主要操作区域。

普通照片查看适用。视频、全景专用查看器、编辑器、人脸编辑模式和幻灯片播放期间隐藏；停止幻灯片后恢复普通查看规则。PC 和移动 Web 均属于本提案范围，手机原生 Flutter 查看器不属于本提案范围。

### 导航缩略图

- 缩略图完整显示当前照片，保持长宽比、旋转方向及编辑结果，与主图一致。
- 白色边框表示主图当前可见范围，框外适度变暗。
- 主图平移、缩放、旋转或视口尺寸改变时，可视框同步更新。
- 拖动可视框可平移主图；点击缩略图其他位置，将该位置移到主视口中心。
- 点击或拖动超出图片有效区域时进行边界约束；没有溢出的轴居中且不允许无意义移动。
- 面板不包含 OCR、人脸框等主图覆盖层，也不触发投屏换图。

导航图复用带现有鉴权、缓存键和 edited 语义的 preview/thumbnail URL。它不创建第二套高分辨率加载器，不因主图变化重新下载原图。

### 缩放控制

PC：导航图下方排列减号、连续滑块、加号；显示当前倍率，并提供“适应窗口”重置。

移动 Web：Navigator 不提供缩放滑块或加减按钮；通过主图双指捏合调整倍率，放大后单指拖动平移。仍支持触摸导航图定位、拖动可视框；导航图上的单指操作不传播为主图切图。现有适用的双击手势规则继续保留。

建议继续使用现有的相对倍率：`1× = 适应窗口`，范围 `1×–10×`。避免直接显示成“100%”，因为现有 zoom=1 并不表示原图像素 1:1。滑块采用对数映射，使低倍率区域更容易微调；加减按钮采用相同的倍率步进。

滑块与按钮以当前视口中心为缩放锚点，调整过程中保持正在查看的区域稳定。Alt＋滚轮、双击、Z、触摸手势、工具栏与面板必须保持同步。普通滚轮切图习惯继续保留；面板内部事件不得冒泡触发主图缩放、双击或切图，滑块可直接拖动而无需按 Alt。

回到 1× 时重置平移并隐藏面板；若键盘焦点在面板内，将焦点交还查看器，避免焦点消失。滑块支持方向键、Home/End 和可访问名称。

## 立即缩放、后台加载与无跳动替换

对正常、浏览器可解码的图片，流程确定为：

1. 感知到放大操作时，主图立即使用当前完整预览图执行缩放，Navigator 同时渐显，后台尝试加载原图。若原图已就绪，直接使用，不额外等待或重复请求。
2. 原图加载期间，用户可继续增减倍率、拖动主图或使用导航图定位。倍率、位置和可视框始终反映实际当前状态，不冻结在发起请求时的状态。
3. 原图加载与解码成功，对应图层准备完成后，在下一次可显示的渲染更新中无感替换预览图。只替换图像来源，沿用替换当时的倍率、视野中心、平移和旋转，不恢复加载开始时的视角，也不等待手势结束。
4. 替换期间不显示空白、不闪回全图、不重建缩放容器、不重置 pointer/手势状态。预览图保留至原图真正可显示，持续拖动或双指捏合不能被打断。
5. 原图加载或解码失败，继续显示并允许缩放/移动当前预览图，倍率和位置保持不变。Navigator 附近显示红色感叹号，提供解释，不弹出阻塞式对话框、不要求先确认是否继续低清缩放。
6. 用户主动缩回 1× 时按普通适应窗口规则重置平移并隐藏 Navigator；后台请求可继续为当前照片完成，完成后只升级图像来源，不能让照片重新放大或使 Navigator 再出现。
7. 切图、关闭查看器、媒体版本变化或进入其他查看模式时清理该照片会话；旧请求即使晚到，也不能影响当前照片、错误状态或视角。

上述规则覆盖 Alt＋滚轮、PC 滑块/按钮、双击、Z、工具栏和触摸缩放。实际变换始终立即生效，不增加“等待高清加载完成才允许缩放”的门槛。

加载阶段允许暂时模糊，失败后仍可继续使用现有预览图。用户通过 Navigator 状态理解原因，不再增加“仍用预览图放大”的二次选择。

### 加载失败提示

红色感叹号放在 Navigator 邻近的固定状态位，不遮挡可视框、滑块或手势操作。建议加载中在同一位置使用轻量的进度指示；原图已准备好且正常显示后移除状态指示。

- PC：悬停、键盘聚焦或点击感叹号都可阅读提示。
- 移动 Web：点击感叹号打开可关闭的说明浮层，不依赖 hover；点击外部关闭。
- 建议失败文案：“原图加载失败，当前显示预览图，可继续缩放和移动。”如提供“重试”，在说明浮层内执行，保留当前倍率、位置和交互，不反复自动重试。
- 错误不只靠颜色传达：感叹号有可访问名称，状态变化可被辅助技术读取。
- 仅当图片原图加载、解码确实失败时显示失败信息；权限限制、格式转换来源和仅有预览图采用匹配的原因说明，不把所有模糊都归因于原文件损坏。
- 用户回到 1× 隐藏 Navigator 时，错误标记随之隐藏；同一照片会话再次放大仍可看到状态，重试成功后清除。切换照片时清除上一张的状态。

### 来源与例外

| 资源条件 | 建议行为 |
| --- | --- |
| 有权限且浏览器可解码 | 立即放大当前预览图，后台加载 original endpoint 返回的原图或现有已编辑高分辨率版本，成功后保持当前视角替换 |
| 原文件不可解码，有 fullsize 可显示版本 | 沿用现有转换/提取图路径，异步升级来源并保持当前视角；来源不能误称为可直接显示的 RAW 原文件 |
| fullsize 实际回退 preview | 继续缩放/移动预览图，状态说明仅预览图可用，不能误报原图已就绪 |
| 分享权限只允许 preview | 遵守原权限，继续缩放/移动预览图并说明限制，不尝试绕过权限下载原图 |
| 加载或解码失败 | 保持当前倍率和位置，继续操作预览图，Navigator 附近显示红色感叹号及可查看的说明 |

正常图片采用上述已明确的立即响应规则。非浏览器兼容格式继续沿用现有来源选择，不在本次默认范围内生成缺失的转换图或重新解码所有 RAW 文件。画质来源与失败原因需明确，但不作为阻塞缩放的前置条件。

需要根据最终响应来源、解码尺寸与媒体版本确认高分辨率是否真实就绪；不能只检查名称为 original 的质量层。对于 fullsize→preview 的重定向，实施时需验证现有请求/Service Worker 链路是否能可靠暴露最终来源。若不能，优先给媒体响应增加明确的来源标记或严格请求选项，并遵守项目 OpenAPI 工作流；不把不可判断的情况直接视作原图。此处具体机制尚未确定。

原图解决来源不足的问题，但超过其原生细节范围的放大仍会插值。Chromium 的 GPU 栅格预算和 HDR 保护需保留；是否需要针对当前倍率重新分配栅格，应通过真实高像素图片测量后决定，不在提案中承诺无限放大仍清晰。

## 状态与坐标设计

沿用 `assetViewerManager` 和 `zoomImageAction` 的单一实际变换状态，导航面板读取同一个状态；图片来源的 idle/loading/ready/error/limited 状态与实际变换独立存储，不保存待高清加载后才应用的倍率。建议面板作为普通照片查看器的未缩放、未旋转兄弟覆盖层，避免面板自身随照片移动。

预览图与原图共用稳定的布局和变换容器，切换质量层不能触发整个查看器或缩放状态重置。使用相同照片版本、方向和编辑结果的逻辑坐标；若实际解码尺寸有差异，通过归一化视野中心映射保持用户正在看的位置，不直接依赖不同图层的 CSS 像素尺寸。

可视框必须按真实图片内容区域计算，而不是简单使用 `1 / zoom` 缩小一个框。现有缩放目标包含整块视口，照片居中且可能有上下或左右留白。

用图片内容区域、视口、平移、缩放和旋转构造统一变换：把视口反向映射到图片坐标，与图片范围求交，再归一化映射到导航图。点击导航图则执行逆操作。90°/270° 旋转、超宽/超长图片、侧栏切换、窗口缩放与 RTL 均使用这套映射。

### 当前缩放库的具体限制

已安装的 `@zoom-image/core 0.42.0` 中，`ZoomImageWheelState` 包含 currentPositionX/Y，但公开的 `ZoomImageWheelStateUpdate` 和 `setState` 实现只接收 enable、zoom、rotation、zoomTarget，并不应用传入的平移坐标。因此直接写 manager.zoomState 的 X/Y 不足以实现导航框拖动。

建议沿用当前库，并通过项目已有的 pnpm patch 机制增加最小的显式平移接口，复用库内部的状态订阅与边界处理；应用层再对真实图片内容约束边界。实现前先验证该小补丁的可行性与手势连续性。避免模拟 PointerEvent 或直接改 DOM transform，否则库状态、下一次拖动和导航框容易分离。若补丁无法满足可靠平移与持续手势，再讨论替换引擎，不默认重写整套手势系统。图片异步加载不为缩放库增加门控。

## 正确性边界

面板的指针、触摸、滚轮和双击事件应在合适层级隔离，复用现有 `data-overlay-interactive` 机制，并支持 pointer capture、pointercancel 与组件销毁清理。状态订阅不得产生循环。

功能成立的判断依据包括：

- 主图和导航框在平移、倍率变化、旋转及打开侧栏后仍一致。
- 首次放大立即响应，Navigator 同时渐显；慢速加载期间继续缩放和移动，替换使用最新视角且不打断进行中的手势。
- 原图加载或解码失败不重置位置与倍率，预览图仍可操作；PC 悬停/点击与移动端点击都能查看红色感叹号的说明。
- PC 有缩放滑块，移动 Web 无缩放条与加减按钮，双指捏合、单指平移和导航图定位可用。
- 快速切图、回到适应窗口、关闭查看器和媒体版本变化后，旧请求不覆盖新图，不恢复旧倍率或错误状态。
- 高分辨率缺失、分享限制、失败与重试均有真实可辨的状态。
- 已编辑照片的主图和导航图保持一致，缓存版本不会串用。
- 普通滚轮切图、Alt＋滚轮、触摸、人脸/OCR 交互和现有 HDR 处理保持可用。
- Chrome、Safari、Firefox 下使用横图、竖图、全景长图、高像素照片、受支持格式及 RAW 转换图进行实际浏览器验证；文档核查不能替代这些验证。
