# 照片查看器导航面板与高分辨率缩放设计

- 决策日期：2026-10-20
- 状态：提案，待讨论；本文不代表已实现或已验证上线
- 范围：Web 普通照片查看器（PhotoViewer）
- 代码核查基线：`0xca71/gallery main c90a67529c5294b2a9e6dddf1dabf6a6e4e6586e`

## 目的与术语

放大查看照片时，用户需要知道自己正看整张照片的哪一部分，并能直观地调整倍率、移动到另一处。新增右上角的导航面板（Navigator），由全图导航缩略图、可视区域框（viewport rectangle）和缩放滑块（zoom slider）组成。

这是照片查看器内的导航，与时间线的缩放导航不同。导航缩略图本身可以使用小图；正在放大检查的主图必须优先使用原图或可解码的高分辨率来源。

术语参考：[GIMP Navigation Dialog](https://docs.gimp.org/2.10/en/gimp-navigation-dialog.html)，其全图预览、可视范围与倍率滑块对应同类交互。

## 当前行为与问题

核查的是源码和已安装依赖，未连接线上实例抓取实际照片请求，也未进行浏览器回归。

| 环节 | 当前代码行为 | 对设计的影响 |
| --- | --- | --- |
| 缩放输入 | `AssetViewer.svelte` 保留 Alt＋滚轮缩放、普通滚轮切图；`PhotoViewer.svelte` 支持双击、Z 和工具栏缩放；`zoom-image.ts` 使用 `@zoom-image/core` | 保留现有输入习惯，新增面板共享同一缩放状态 |
| 清晰度加载 | `AdaptiveImage.svelte` 在实际 `zoom > 1` 后触发名为 `original` 的质量层 | 目前是先放大再加载，不能保证放大的第一帧已经清晰 |
| 浏览器可解码图片 | `web/src/lib/utils.ts` 的 `targetImageSize` 在强制原图时选择 original endpoint | 普通兼容图片已有原图请求路径，不能笼统认定一直在放大小缩略图 |
| 浏览器不兼容格式 | 同一方法选择 fullsize endpoint | RAW 等需要转换或提取后的可显示图，不能直接把不可解码原文件塞入 img |
| fullsize 缺失 | `AssetMediaService.viewThumbnail` 会重定向回 preview | “original 层加载成功”不等于原图或全尺寸图真实可用 |
| RAW 内嵌图 | `MediaService.extractOriginalImage` 可使用内嵌 JPEG 生成或保存 fullsize | fullsize 是来源类别，不应无条件宣称等于传感器原始分辨率 |
| 已编辑图片 | 媒体 URL 默认携带 `edited=true`，原图服务可返回 editedPath | 放大后应继续显示用户看到的编辑结果，不能突然显示未编辑版本 |
| 分享限制 | `getAssetUrl` 对不允许下载或不显示元数据的分享返回 preview；原图接口检查 AssetDownload 权限 | 不可用直接原图请求绕过权限；受限情况下需明确画质状态 |
| Chromium 渲染 | `AdaptiveImage.svelte` 有 HDR 接缝和 GPU 栅格预算处理 | 已加载原图仍可能受渲染分辨率限制，不能以移除保护换取潜在缺块 |

## 建议的交互

### 显示与布局

在用户请求放大或已放大时，右上角显示导航面板；适应窗口时隐藏。面板位于顶部工具栏下面，默认宽约 180–220 CSS 像素，使用现有主题的深色半透明背景、细边框与适量圆角。

面板相对实际照片可视区域定位。打开详情或活动侧栏时，避开侧栏；工具栏显隐不应使面板跳动。高度受可视区域限制，竖图不能占满屏幕。窄屏收窄面板，保留可操作的滑块与按钮。

普通照片查看适用。视频、全景专用查看器、编辑器、人脸编辑模式和幻灯片播放期间隐藏；停止幻灯片后恢复普通查看规则。手机原生 Flutter 查看器不属于本提案范围，Web 触屏仍需正常工作。

### 导航缩略图

- 缩略图完整显示当前照片，保持长宽比、旋转方向及编辑结果，与主图一致。
- 白色边框表示主图当前可见范围，框外适度变暗。
- 主图平移、缩放、旋转或视口尺寸改变时，可视框同步更新。
- 拖动可视框可平移主图；点击缩略图其他位置，将该位置移到主视口中心。
- 点击或拖动超出图片有效区域时进行边界约束；没有溢出的轴居中且不允许无意义移动。
- 面板不包含 OCR、人脸框等主图覆盖层，也不触发投屏换图。

导航图复用带现有鉴权、缓存键和 edited 语义的 preview/thumbnail URL。它不创建第二套高分辨率加载器，不因主图变化重新下载原图。

### 缩放控制

导航图下方排列：减号、连续滑块、加号；显示当前倍率，并提供“适应窗口”重置。

建议继续使用现有的相对倍率：`1× = 适应窗口`，范围 `1×–10×`。避免直接显示成“100%”，因为现有 zoom=1 并不表示原图像素 1:1。滑块采用对数映射，使低倍率区域更容易微调；加减按钮采用相同的倍率步进。

滑块与按钮以当前视口中心为缩放锚点，调整过程中保持正在查看的区域稳定。Alt＋滚轮、双击、Z、触摸手势、工具栏与面板必须保持同步。普通滚轮切图习惯继续保留；面板内部事件不得冒泡触发主图缩放、双击或切图，滑块可直接拖动而无需按 Alt。

回到 1× 时重置平移并隐藏面板；若键盘焦点在面板内，将焦点交还查看器，避免焦点消失。滑块支持方向键、Home/End 和可访问名称。

## 原图准备好后再放大

建议区分“用户请求的倍率”和“当前实际显示的倍率”，不再用已经改变的实际倍率作为加载原图的唯一触发条件。

1. 第一次请求超过 1× 时，触发当前照片的高分辨率来源加载，主图暂时保持适应窗口。
2. 面板立即出现，显示“正在加载原图”或与实际来源匹配的状态。记录最新的目标倍率及锚点，连续操作只更新同一请求。
3. 资源加载并解码、对应主图层准备完成后，再应用最新目标倍率与位置，避免先放大小图再突然变清晰。
4. 已加载的高分辨率图在当前照片的查看生命周期内复用；后续缩放不重复等待。
5. 用户退回 1×、切换照片、关闭查看器或进入编辑模式时，取消待应用意图。异步结果按照片 ID、版本/缓存键与请求代次校验，不能影响下一张照片。
6. 加载失败时保留当前可浏览图片，显示失败和重试入口，不无限加载、不静默当成原图成功。默认不执行尚未得到高分辨率来源的放大。

双击、触摸及缩放库自身的输入也必须经过这道准备逻辑；只拦截 Alt＋滚轮或滑块不能满足要求。

### 来源与例外

| 资源条件 | 建议行为 |
| --- | --- |
| 有权限且浏览器可解码 | 加载 original endpoint 返回的原图，或现有已编辑高分辨率版本，然后放大 |
| 原文件不可解码，有 fullsize 可显示版本 | 使用 fullsize，明确这是高分辨率转换/提取图；按实际解码尺寸计算画质与几何 |
| fullsize 实际回退 preview | 标识“仅预览图可用”，默认不把它当成高分辨率就绪 |
| 分享权限只允许 preview | 遵守原权限，标识画质限制，不尝试绕过权限下载原图 |
| 加载或解码失败 | 保持适应窗口并允许重试 |

待讨论的例外策略：仅预览图可用时，是否提供一个明确的“仍用预览图放大”选择。建议不要默认静默降级。生成缺失的转换图或重新解码所有 RAW 文件不在本次默认范围内。

需要根据最终响应来源、解码尺寸与媒体版本确认高分辨率是否真实就绪；不能只检查名称为 original 的质量层。对于 fullsize→preview 的重定向，实施时需验证现有请求/Service Worker 链路是否能可靠暴露最终来源。若不能，优先给媒体响应增加明确的来源标记或严格请求选项，并遵守项目 OpenAPI 工作流；不把不可判断的情况直接视作原图。此处具体机制尚未确定。

原图解决来源不足的问题，但超过其原生细节范围的放大仍会插值。Chromium 的 GPU 栅格预算和 HDR 保护需保留；是否需要针对当前倍率重新分配栅格，应通过真实高像素图片测量后决定，不在提案中承诺无限放大仍清晰。

## 状态与坐标设计

沿用 `assetViewerManager` 和 `zoomImageAction` 的单一实际状态，导航面板读取同一个状态；待加载的缩放意图与实际变换分开存储。建议面板作为普通照片查看器的未缩放、未旋转兄弟覆盖层，避免面板自身随照片移动。

可视框必须按真实图片内容区域计算，而不是简单使用 `1 / zoom` 缩小一个框。现有缩放目标包含整块视口，照片居中且可能有上下或左右留白。

用图片内容区域、视口、平移、缩放和旋转构造统一变换：把视口反向映射到图片坐标，与图片范围求交，再归一化映射到导航图。点击导航图则执行逆操作。90°/270° 旋转、超宽/超长图片、侧栏切换、窗口缩放与 RTL 均使用这套映射。

### 当前缩放库的具体限制

已安装的 `@zoom-image/core 0.42.0` 中，`ZoomImageWheelState` 包含 currentPositionX/Y，但公开的 `ZoomImageWheelStateUpdate` 和 `setState` 实现只接收 enable、zoom、rotation、zoomTarget，并不应用传入的平移坐标。因此直接写 manager.zoomState 的 X/Y 不足以实现导航框拖动。

建议沿用当前库，并通过项目已有的 pnpm patch 机制增加最小的显式平移接口，复用库内部的状态订阅与边界处理；应用层再对真实图片内容约束边界。实现前先验证该小补丁的可行性与手势连续性。避免模拟 PointerEvent 或直接改 DOM transform，否则库状态、下一次拖动和导航框容易分离。若补丁无法同时满足加载门控和可靠平移，再讨论替换引擎，不默认重写整套手势系统。

## 正确性边界

面板的指针、触摸、滚轮和双击事件应在合适层级隔离，复用现有 `data-overlay-interactive` 机制，并支持 pointer capture、pointercancel 与组件销毁清理。状态订阅不得产生循环。

功能成立的判断依据包括：

- 主图和导航框在平移、倍率变化、旋转及打开侧栏后仍一致。
- 首次放大只有在正确的高分辨率图准备好后才发生；快速切图没有旧请求覆盖新图。
- 高分辨率缺失、分享限制、失败与重试均有真实可辨的状态。
- 已编辑照片的主图和导航图保持一致，缓存版本不会串用。
- 普通滚轮切图、Alt＋滚轮、触摸、人脸/OCR 交互和现有 HDR 处理保持可用。
- Chrome、Safari、Firefox 下使用横图、竖图、全景长图、高像素照片、受支持格式及 RAW 转换图进行实际浏览器验证；文档核查不能替代这些验证。
